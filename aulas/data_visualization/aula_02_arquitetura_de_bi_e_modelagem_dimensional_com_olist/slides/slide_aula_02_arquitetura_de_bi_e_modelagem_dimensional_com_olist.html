Arquitetura de BI · 8h35–8h43

Uma solução de BI distribui responsabilidades entre camadas

FontesERP, CRM, arquivos, APIs, logs e bancos operacionais.
MovimentaçãoConectores, Power Query, ETL/ELT, streaming e gateway.
PersistênciaWarehouse, lakehouse, marts, séries temporais e índices.

A mesma ferramenta pode ocupar mais de uma camada. A análise arquitetural identifica onde cada responsabilidade está efetivamente executada e persistida.

Arquivo PBIXReúne definição de consultas, modelo semântico e relatório; no modo Import, também contém a cópia comprimida dos dados.
Power BI · Publicação e consumo

Service e Report Server constituem destinos distintos

Service: SaaS em nuvem. Report Server: hospedagem local, com ciclo e conjunto de recursos próprios. “Power BI Server” precisa ser qualificado para evitar ambiguidade.

Grafana · Consulta orientada a painéis

O servidor consulta fontes externas e mantém seu próprio estado

Grafana atende casos de BI quando o trabalho exige painéis, filtros, SQL e consumo recorrente; sua origem em observabilidade favorece séries temporais, atualização frequente e alertas.

Metabase · Arquitetura da disciplina

O projeto separa estado da aplicação e dados analíticos

As perguntas salvas guardam definições no banco da aplicação. A execução consulta o Olist; resultados persistentes exigiriam cache, modelo persistido ou transformação autorizada.

Arquitetura de dados · 9h15–9h25

PerguntaQual decisão o gráfico precisa sustentar?

  1. Abra New → SQL query e selecione Olist.
  2. Use generate_series entre a menor e a maior data de compra.
  3. Crie sk_data no formato AAAAMMDD e atributos de ano, trimestre, mês e dia.

Atividade 3 · 10h38–10h50

Versione a dimensão cliente com SCD Tipo 2

  1. Una olist_customers a olist_orders por customer_id.
  2. Ordene observações por customer_unique_id e data de compra.
  3. Compare CEP, cidade e estado com LAG; marque cada mudança.
  4. Acumule as mudanças para numerar versões e calcule valid_from/valid_to.

Validade temporalUm fato de compra associa-se à versão em que compra >= valid_from e compra < valid_to; valid_to vazio identifica a versão vigente.

CROSS JOIN · 11h26–11h32

O produto cartesiano cria uma grade analítica completa

WITH meses AS (...), ufs AS (...), grade AS ( SELECT mes, uf FROM meses CROSS JOIN ufs ), observado AS (...) SELECT grade.mes, grade.uf, coalesce(observado.pedidos, 0) AS pedidos FROM grade LEFT JOIN observado USING (mes, uf);

Aplicação

Mostrar meses sem pedido com valor zero e preservar comparações entre UFs.

Controle

O total de linhas da grade é o produto das cardinalidades. Filtre domínios antes do cruzamento.

Drill-across · 11h32–11h38

Fatos separados são alinhados por dimensões conformadas

Drill-across é uma operação de integração analítica entre processos. Drill-down descreve navegação para maior detalhe dentro de uma hierarquia.
